Duas camadas. Componente só enxerga a de cima.

Primitivos são a escala bruta de valores possíveis e não carregam significado de uso. Semânticos são apelidos nomeados pelo papel que cumprem na interface. Separar os dois é o que permite trocar a aparência inteira do produto sem reabrir um único componente.

Por que não bastam os primitivos

A marca tem oito cores fixas e nenhum modo escuro previsto. Ainda assim a camada semântica vale — por dois motivos concretos.

Primeiro: a regra "vermelho é só ação" só é executável se o componente escrever var(--asa-action). Escrevendo var(--asa-red), a regra continua sendo folclore que alguém precisa lembrar. Segundo: a v3.1 troca vermelho e amarelo de papel. Isso é literalmente um tema — e sem apelido seria reescrever todo componente para produzir a variante B2B.

Os quatro arquivos
asa-tokens.css@font-face + as duas camadas
asa-base.cssreset, elementos, layout, foco
asa-components.cssa biblioteca inteira
asa-utilities.csscorte 8°, hachura, auxiliares

Nesta ordem. Sem build, é a cascata por ordem de origem que dispensa !important — utilitário por último para poder vencer componente quando precisar.

Convenção
Bloco.asa-btn
Elemento.asa-card__price
Modificador.asa-btn--primary
Estadoatributo nativo

Estado de runtime nunca vira classe: :disabled, [aria-invalid], [data-state="loading"], [aria-current="step"]. É o que o framework já emite, e traz acessibilidade junto de graça.

A variante B2B em nove linhas
/* asa-tokens-v31.css — carregar DEPOIS de asa-tokens.css. Nenhum componente muda. Nenhuma classe muda. Só o papel das cores. */ :root { --asa-surface: var(--asa-red); /* vermelho vira ambiente */ --asa-bg: #FFF2F2; /* creme frio da v3.1 */ --asa-action: var(--asa-yellow); /* amarelo vira ação */ --asa-on-action: var(--asa-black); /* sobre amarelo, só preto */ --asa-action-hover: #EAB227; }

Esta é a prova de que a camada semântica não é cerimônia. Com ela, a variante B2B é um arquivo de cinco declarações. Sem ela, seria uma caça manual a cada lugar do produto onde #E80911 foi escrito direto.

Tipografia, espaço, forma, ícone e movimento.

Tipografia
--asa-fontBR Omny + fallback
--asa-fs-display64px
--asa-fs-title32px
--asa-fs-highlight20px
--asa-fs-body16px
--asa-fs-label12px

Não existe token composto de tipografia. O atalho font não carrega letter-spacing nem text-transform, e quatro dos cinco degraus dependem de um ou de outro — um token composto reintroduziria a chance de erro exatamente onde o sistema é mais frágil.

Espaço e grade
--asa-space-1…114 a 90px
--asa-container-max1200px
--asa-gutter24px
--asa-columns12 / 8 / 4
--asa-safe-fold680px

Breakpoints existem como token para leitura e para JS, mas as media queries repetem o valor literal: custom property não funciona dentro de @media.

Forma e tamanho
--asa-radius4px
--asa-radius-full50% · só avatar
--asa-border-width1.5px
--asa-control-h48px
--asa-touch-min44px
--asa-icon-inline24px
--asa-icon-stroke1.5

Só dois valores de raio, e é de propósito: uma escala sm/md/lg convidaria alguém a escolher entre eles. O sistema não oferece essa escolha.

Coleção que não existe Sombra

Não há --asa-shadow-*. Isso é decisão registrada, não lacuna.

A marca é chapada: elevação se resolve com borda de 1,5px e contraste de fundo, e foco se resolve com outline. Se um dia alguém precisar de box-shadow, o problema é o layout, não a falta do token.

Sob prefers-reduced-motion, as quatro durações caem para 1ms na própria camada de tokens — nenhum componente precisa lembrar disso.

Como consumir

Cole os quatro arquivos. Não há build, não há dependência.

HTML puro, WordPress, qualquer coisa
<link rel="stylesheet" href="css/asa-tokens.css"> <link rel="stylesheet" href="css/asa-base.css"> <link rel="stylesheet" href="css/asa-components.css"> <link rel="stylesheet" href="css/asa-utilities.css"> <!-- e o markup já nasce na marca --> <h1>Seu carro já tá te esperando</h1> <button class="asa-btn asa-btn--primary"> <span class="asa-btn__label">Ver carros</span> </button>
React, Vue, Svelte
// importe uma vez, na raiz import './css/asa-tokens.css' import './css/asa-base.css' import './css/asa-components.css' import './css/asa-utilities.css' // o estado é atributo, não classe — nada de // className={loading ? 'btn--loading' : ''} <button className="asa-btn asa-btn--primary" data-state={loading ? 'loading' : undefined} disabled={loading} >
Migrando para CSS Modules, Tailwind ou styled-components

A camada de tokens vai inteira, sem tradução: são custom properties, e todo sistema de estilo lê custom property. O que muda é só a camada de componente. Se o destino for Tailwind, mapeie os tokens no theme.extend apontando para as mesmas variáveis — não copie os valores hexadecimais para lá, senão as duas fontes de verdade divergem na primeira mudança de marca.
